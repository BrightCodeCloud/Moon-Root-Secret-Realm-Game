结论：可以开始春季垂直切片开发；核心玩法不再缺设定，图片已有原型占位与生产锚点。最终运行时动画、无缝 Tileset、字体和音频应在开发阶段清稿与接入，不能误报为已经完成。

## 1. 审计方法

本次按三层核对：

1. 设计文档是否明确说明玩法、数值、存档、难度、积分和验收标准。
2. 视觉清单与 JSON 清单中的路径是否真实存在。
3. 实际图片是否具备正确尺寸、透明通道、统一画风和可识别用途。

核对结果：

- `character-assets.json` 原有 29 项路径全部存在。
- `environment-assets.json` 原有 8 项路径全部存在。
- `gameplay-visual-assets.json` 原有 16 项路径全部存在。
- 抽查和脚本检查的 44 张透明运行时/占位 PNG 四角均为透明。
- 四关背景统一为 1672×941；角色主图统一为 1254×1254 RGBA；既有语义图集统一为 1254×1254 RGBA。
- 现有角色主图、背景、UI 和弹幕的像素语言、深蓝/暖橙/青色配色与《美术与 UI 规范》一致。

## 4. 开发启动门槛

### 已满足，可以开始

- 春季 9–11 房完整流程有明确房间构成。
- 3 把武器、4 种种子、4 种敌人、1 种精英、1 个 Boss 都有数值和视觉锚点。
- 月根网络、生态配方、天气、收割/留根和 Boss 继承有规则、UI 图标与验收指标。
- 商店、温室、继续游戏、难度和排行榜有交互规则与布局参考。
- 自动存档字段、继续规则、回溯局和积分公式已经确定。
- 战斗弹幕、激光、近战、预警、击杀、破坏、门、陷阱和掉落物已有图集。

### 开发中必须完成

1. 把角色主图与关键姿势板清稿为固定网格动画。
2. 把模块板清稿为真正无缝的 16×16 Tileset。
3. 将大图集重打包为整数单元格运行时图集，不能直接使用 `Hframes=4` 猜测切分。
4. 制作中文字体授权表、音效清单与音频文件。
5. 在 320×180 或 480×270 设计分辨率下验证弹幕、UI 字号与图标可读性。
6. 为键鼠和手柄完成焦点顺序、重绑定和断连测试。

这些任务属于开发与清稿，不需要再等待新的概念设定或同类高分辨率图片。

## 5. 建议的第一周接入顺序

1. 先导入春季战斗房、莱芽静态占位、芽枝杖、4 种植物和基础弹体。
2. 实现一个战斗房的播种、成长、收割与留根。
3. 接入月根图标和地图参考，只验证两个房间节点传播。
4. 接入泥团芽、刺萝卜与苔冠刺萝卜，验证预警和威胁调度。
5. 加入商店、温室和安全存档节点。
6. 最后接入 Boss 和基础结算，再扩展到 9–11 房完整流程。

如果第二步的“种植—留根—跨房影响”不成立，应优先修改核心规则，而不是继续增加后续关卡资产。
